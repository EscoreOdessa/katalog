# ESCORE — Пошук обладнання у постачальників

Веб-каталог, який дозволяє проєктанту чи менеджеру знайти обладнання за характеристиками
і одразу побачити, **у кого воно є в наявності** та **посилання на datasheet**.

**Живий сайт:** https://escoreodessa.github.io/katalog/

> **Цін немає навмисно.** Каталог показує лише модель, постачальника, наявність і datasheet —
> це інструмент підбору, а не прайс.

## Що шукаємо

| Категорія | Фільтри пошуку | Бренди |
|-----------|----------------|--------|
| **Інвертори** | потужність (кВт, від/до), фазність (1/3), напруга АКБ (HV/LV) | тільки Deye |
| **Батареї** | ємність (кВт·год, від/до), напруга (HV/LV) | тільки Deye |
| **Панелі** | потужність (Вт, від/до) | будь-який бренд |

Скрізь є перемикач **«лише в наявності»**.

## Як це працює

Три частини, повністю статичний хостинг (GitHub Pages), без сервера й без бази даних:

```
джерела постачальників ──►  build.mjs  ──►  catalog.json  ──►  index.html (пошук)
     (раз на добу, GitHub Actions)              (дані)          (статична сторінка)
```

1. **`build.mjs`** — збирач. Раз на добу ходить по всіх джерелах постачальників, розбирає їхні
   назви/наявність у єдиний формат і перезаписує `catalog.json`.
2. **`catalog.json`** — готові дані каталогу (масив позицій).
3. **`index.html`** — сторінка пошуку. Завантажує `catalog.json` і фільтрує його у браузері.

Оновлення автоматичне: GitHub Action `refresh-catalog` запускається **щодня о 05:00 UTC**
(а також вручну — вкладка **Actions → refresh-catalog → Run workflow**). Якщо дані змінились —
бот комітить новий `catalog.json`, і GitHub Pages за хвилину показує оновлення.

## Як працює пошук (наприклад, за потужністю)

Пошук працює у два етапи:

**1. Під час збірки потужність витягується з назви в число.**
`build.mjs` розбирає назву кожної позиції та кладе потужність в окреме числове поле:

- панель `Longi Hi-MO X10 LR7-72HVD 650W` → `watt: 650`
- інвертор `Deye SUN-20K-G04` → `kw: 20`
- батарея `Deye … 5,12 кВт·год` → `kwh: 5.12`

Тобто число нормалізується **один раз при збірці**, тому по ньому можна шукати однаково
по всіх постачальниках.

**2. Під час пошуку йде порівняння діапазону.**
Коли ти вводиш «від 600» і «до 650» у вкладці «Панелі», сторінка лишає позиції, у яких
`watt` потрапляє в діапазон (`watt ≥ 600` і `watt ≤ 650`). Порожнє поле = без обмеження.
Зверху накладаються інші фільтри (наявність, фазність, HV/LV), а результат сортується так,
щоб позиції «в наявності» були вгорі.

> **Обмеження:** потужність береться з **тексту назви** за шаблоном. Якщо постачальник
> написав назву нестандартно і числа в ній немає — позиція може не потрапити під фільтр
> потужності (у списку вона залишиться). Такі випадки поодинокі; їх можна донастроїти в `build.mjs`.

## Джерела даних

Наявність береться **зі слів постачальника** — перед замовленням варто підтверджувати.

| Постачальник | Тип джерела | Оновлюється сам | Примітка |
|--------------|-------------|:---------------:|----------|
| YugTorg | сайт із логіном (cookie) | ✅ | секрет `YUGTORG_COOKIE` |
| Atmo (Atmosfera) | сайт із логіном (внутрішній API) | ✅ | секрети `ATMO_EMAIL`, `ATMO_PASSWORD` |
| Sakoenergy | Google Sheet (публічний) | ✅ | gviz CSV |
| Intersolar | Google Sheet (публічний) | ✅ | gviz CSV |
| Helius | Google Sheet (публічний) | ✅ | gviz CSV |
| SunRise | Google Sheet (публічний) | ✅ | gviz CSV |
| Solarity | приватна таблиця постачальника → **публічне дзеркало** | ✅ | див. нижче |
| Altek | Google Sheet | ⏳ | поки статичний снимок |
| Vimmer | Google Sheet | ⏳ | поки статичний снимок |

**Стійкість:** якщо якесь джерело тимчасово не відповіло (протух cookie, недоступний сайт),
його позиції беруться з попереднього знімка — каталог не «обнуляється».

### Наявність

- 🟢 **В наявності** — є на складі постачальника
- 🟡 **Очікується** — під замовлення / в дорозі / незабаром
- ⚪ **Немає** — немає в наявності

## Дзеркало Solarity

Таблиця Solarity належить постачальнику і приватна, тому GitHub Action не може читати її напряму.
Рішення — **публічне дзеркало** у Google Sheets на акаунті ESCORE, яке тягне дані через `IMPORTRANGE`:

- дзеркало: `1i3u_awTfs-TMYt1YvHqXmfzguB_ThPGSt4bJYh4vg70` (доступ «Всім, хто має посилання — Переглядач»)
- 3 вкладки: **panels** ← `PV modules`, **inv** ← `Гібридні інвертори`, **bat** ← `Акумулятори`

Дзеркало тримається на доступі ESCORE до таблиці постачальника. Якщо постачальник закриє доступ —
дзеркало спорожніє, але каталог не зламається (Solarity лишиться зі знімка).

## Структура `catalog.json`

```json
{
  "generated": "2026-08-17",
  "note": "...",
  "items": [
    { "cat": "inv", "model": "Deye SUN-12K-SG04LP3", "sup": "YugTorg", "avail": "yes", "kw": 12, "ph": 3, "hv": false },
    { "cat": "bat", "model": "Deye BOS-G Pro 5.12", "sup": "Solarity", "avail": "yes", "kwh": 5.12, "hv": true },
    { "cat": "pan", "model": "Longi 650W", "sup": "Sakoenergy", "avail": "soon", "watt": 650, "ds": "https://…" }
  ]
}
```

- `cat` — `inv` | `bat` | `pan`
- `avail` — `yes` | `soon` | `no`
- `ds` — посилання на datasheet (за наявності)

## Обслуговування

**Секрети** (Settings → Secrets and variables → Actions): `YUGTORG_COOKIE`, `ATMO_EMAIL`, `ATMO_PASSWORD`.
Якщо в логах прогону біля постачальника `0 позицій` або «не авторизовано» — оновіть відповідний секрет.

**Ручний запуск / перевірка:** Actions → **refresh-catalog** → **Run workflow**. У логах кроку
*Build catalog* видно, скільки позицій дало кожне джерело.

**Категорії обходу** задані масивами в `build.mjs`: `YUG_CATS` (YugTorg), `ATMO_CATS` (Atmo),
`SHEETS_LIVE` (Google-таблиці). Datasheet-посилання — у резолвері `datasheetFor()`.

## Файли репозиторію

- `index.html` — сторінка пошуку (весь UI в одному файлі)
- `catalog.json` — дані каталогу (оновлюються ботом)
- `build.mjs` — збирач каталогу з усіх джерел
- `.github/workflows/refresh.yml` — розклад автооновлення
